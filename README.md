# hxyfront-62004 滑雪板调校维护 · 放行账

源提示词编号：6

面向滑雪板调校店的装备维护前端系统。雪板档案、刃角工单、刃角方案、技师资质四本账接成一套**放行账**，核心规则：

1. **开工放行**：开工前按客户确认的方案、最新边刃厚度（低于板型下限禁止再磨）、技师角色权限（学徒不得磨刃、竞速板磨刃须老师傅）判断，任一不满足就不放行，放行与拒放都记账。
2. **偏好失效**：客户改动刃角偏好，偏好版本 +1，该板所有方案立刻失效，未完工工单退回待确认。
3. **并发拒写**：档案/方案/工单均带乐观锁版本，两台平板同时改同一块板，只接受先写的一边，后写的收到版本冲突并被拒。
4. **旧数据升级**：迁移时缺刃角方案（或缺边刃厚度）的雪板一律标成待复核，复核前放行检查必拦。
5. **写库重试**：写库按批次分步执行，每步落库即在步骤账记账；失败后重试只补跑尚未记账的步骤，已记账步骤凭幂等键跳过。

## 技术栈

React + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62004

## 校验

```bash
npm run typecheck   # 类型检查
npm test            # vitest：放行检查 / 偏好失效 / 并发拒写 / 迁移待复核 / 写库重试
npm run build       # 生产构建
```

## 目录

- `src/domain/types.ts` — 雪板档案、刃角方案、刃角工单、技师、放行账条目
- `src/domain/release.ts` — 开工放行检查（纯函数）
- `src/domain/store.ts` — 放行账核心：乐观锁、偏好失效、放行记账
- `src/domain/migration.ts` — 旧数据升级，缺方案标待复核
- `src/domain/pipeline.ts` — 写库管线：步骤记账 + 幂等重试
- `tests/` — 上述规则的 vitest 用例
